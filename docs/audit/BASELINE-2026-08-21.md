### Detalhe das 17 falhas de backend

**`NexTraceOne.Integrations.Tests` — 13 falhas — BUG DE PRODUÇÃO**
Todas com `System.ArgumentException : Tenant-scoped connectors must have a TenantId`
originada em `IntegrationConnector.Create` (`IntegrationConnector.cs:124`).

Verificado: os 12 pontos de chamada de produção em `NexTraceOne.Ingestion.Api/Endpoints/`
também não passam `tenantId` nem `isGlobal`, logo lançam em runtime no auto-provisionamento
do conector. `tenantId` e `isGlobal` são parâmetros opcionais, por isso o compilador não
obrigou nenhum chamador a mudar quando a invariante foi introduzida.

- `IntegrationHubFeatureTests`: `GetConnector_ValidId_ShouldReturnConnector`, `GetFreshness_ShouldReturnFreshnessSummary`, `GetHealth_ShouldReturnValidHealthSummary`, `GetIntegrationFilterOptions_ShouldReturnDistinctConnectorTypesAndSupportedStates`, `ListConnectors_WithData_ShouldReturnItems`, `ListExecutions_WithData_ShouldReturnItems`, `ListSources_WithData_ShouldReturnItems`, `ReprocessExecution_ValidId_ShouldReturnQueued`, `RetryConnector_ValidId_ShouldReturnQueued`
- `RetryConnectorTests`: `RetryConnector_ValidConnectorId_ShouldCreateExecutionAndReturnQueued`
- `IngestionPayloadParserTests`: `IngestionExecution_DefaultProcessingStatus_IsMetadataRecorded`, `IngestionExecution_MarkAsFailed_SetsFailedStatus`, `IngestionExecution_MarkAsProcessed_SetsAllParsedFieldsAndStatus`

**`NexTraceOne.BuildingBlocks.Security.Tests` — 3 falhas**
`AesGcmEncryptorTests`: `Decrypt_WithInvalidBase64_Throws`, `Decrypt_WithPayloadTooShort_Throws`,
`Decrypt_WithTamperedCiphertext_Throws` — todas *"Expected a `<System.FormatException>` to be
thrown, but no exception was thrown"*.

A implementação declara explicitamente o comportamento oposto:

> `/// <remarks>Fail-open: se o valor não for um ciphertext válido, retorna o texto original.</remarks>`

Não é um teste a apanhar uma regressão acidental — é um contrato contraditório entre
implementação e testes. O caso `Decrypt_WithTamperedCiphertext_Throws` é o relevante para
segurança: adulteração de ciphertext é silenciosamente ignorada.

**`NexTraceOne.Governance.Tests` — 1 falha**
`TestNetworkConnectivityTests.Handle_WhenTargetIsAccessible_ShouldReturnSuccessWithStatusCode`
— *"Expected result.Value.Success to be True, but found False"*. O teste faz um pedido HTTP
real; falha em ambientes sem egresso direto. Dependente de ambiente.

## `.NET Dependency Scan` — o gate aborta antes de verificar

O passo em `.github/workflows/security.yml`:

```bash
dotnet list NexTraceOne.sln package --vulnerable --include-transitive 2>&1 | tee /tmp/vuln-report.txt
if grep -q "has the following vulnerable packages" /tmp/vuln-report.txt; then
  echo "::error::Vulnerable NuGet packages detected. Review /tmp/vuln-report.txt"
  cat /tmp/vuln-report.txt
  exit 1
fi
```

O shell por omissão do GitHub Actions é `bash --noprofile --norc -eo pipefail`. Com
`pipefail`, o estado do pipeline é o do `dotnet list`, que sai com **1** porque:

```
The project `src/frontend/nextraceone.frontend.esproj` uses package.config for NuGet
packages, while the command works only with package reference projects.
```

Com `-e`, o passo termina nessa linha. **O `grep` e a mensagem `::error::Vulnerable NuGet
packages detected` nunca executam.** No log do CI vê-se apenas o erro do `.esproj`.

As vulnerabilidades são reais — reproduzido localmente com o mesmo comando:

```
> Microsoft.OpenApi   2.0.0      High   GHSA-v5pm-xwqc-g5wc
> SSH.NET             2025.1.0   High   GHSA-q939-rpr3-3284
```

5 projetos afetados (`has the following vulnerable packages` aparece 5 vezes), coerente
com os 7 avisos `NU1903` do build.

O efeito líquido não é um falso-verde — o job fica vermelho, como deve. É uma
**falha misatribuída**: quem lê o log conclui que o problema é a configuração do `.esproj`,
quando há também duas vulnerabilidades altas por corrigir.

Correção: excluir o `.esproj` do comando ou filtrar os projetos analisados.
